# Template language

Adapted from the source engine’s requirements. The Tcl package passes JSON object
contexts to this engine and exposes its loader through `-templates`; see
[the command reference](../readme.md). This is a subset, not full Python Jinja2.

The supported subset is intentionally smaller than Python Jinja2 and Jinja2Cpp. It includes:

- `{{ expression }}` output, with HTML auto-escaping for ordinary string values. Values produced by `escape`/`e`, `safe`, `tojson`, macros, and block captures are marked safe and are not escaped again. Use `safe` only for trusted/template-authored markup, never for untrusted data.
- variable lookup from the root cJSON object. The renderer does not create implicit aliases for the root object; names such as `this` and `product` are available only when the root cJSON object defines those keys.
- dot and bracket lookup, string and list slices (`value[:end]`, `value[start:]`, and `value[start:end]`), string/number/boolean/null/list/object/tuple literals (`[]`, `[expr, ...]`, `{key: expr}`, and `(expr, ...)`), inline conditional expressions (`value if condition else fallback` and compatibility form `condition ? value : fallback`), arithmetic including `//` and `**`, list concatenation with `+`, string concat with `~`, comparisons, `in` / `not in`, the `is defined` / `is not defined` / `is undefined` tests, the `is none` / `is not none` test, basic value tests (`even`, `odd`, `string`, `number`, `iterable`, `mapping`, `sequence`, `lower`, `upper`, `eq`, `ne`, `gt`, `ge`, `lt`, `le`), logical `and`/`or`/`not`, built-in `range(stop)`, `range(start, stop)`, and `range(start, stop, step)` for bounded numeric loops, and allowlisted non-mutating value methods (`split`, `join`, `strip`/`trim`, `lower`, `upper`, `replace`, `startswith`, `endswith`, `keys`, `values`, `items`, and `get`)
- `{% set name = expression %}` and block capture with `{% set name %}...{% endset %}` or `{% set name | filter %}...{% endset %}`. `set` updates the nearest existing binding in the active scope stack; if no binding exists, it creates a binding in the current scope. Loop variables and macro parameters remain local bindings.
- `{% if %}`, `{% elif %}`, `{% else %}`, `{% endif %}`
- `{% for item in collection %}`, multiple loop variables/unpacking (`{% for key, value in collection %}`), loop filtering (`{% for item in collection if condition %}`), optional `{% else %}`, `{% endfor %}`, and loop metadata `loop.index`, `loop.index0`, `loop.first`, `loop.last`, and `loop.length`
- macros declared with `{% macro name(param, default='value') %}` and called as `{{ name(arg) }}` with positional or keyword arguments. Calling an undefined macro is a hard validation and render error. A bare macro reference such as `{{ icon|safe }}` renders the macro only when it has zero required parameters; macros with required parameters still require an explicit call. Call blocks are supported with `{% call macro(arg) %}...{% endcall %}` and optional caller parameters such as `{% call(item) render_list(items) %}...{% endcall %}`; the target macro renders the block by calling `{{ caller() }}` or `{{ caller(item) }}`.
- constant-path `{% include 'path/to/template.html.jinja' %}` using the current render context
- root-level constant-path `{% extends 'path/to/layout.html.jinja' %}`, `{% block name %}...{% endblock %}`, optional `{% endblock name %}`, and `{{ super() }}` inside overridden blocks. An extending template renders the parent/root template and substitutes child blocks, but it does not execute top-level child nodes outside blocks. Therefore templates with `extends` may contain only whitespace and block statements at template root level; includes, macros, outputs, assignments, conditionals, loops, call blocks, and non-whitespace text must be inside a block.
- filters `escape`/`e`, `default`/`d`, `length`, `attr`, `lower`, `upper`, `capitalize`, `title`, `trim`, `join`, `first`, `last`, `safe`, `tojson`, `replace`, `format`, `reverse`, `sort`, `min`, `max`, `sum`, `groupby`, `map`, `reject`, `rejectattr`, `select`, `selectattr`, `unique`, `int`, `float`, `abs`, `round`, `list`, `dictsort`, `batch`, `slice`, `truncate`, `urlencode`, `wordcount`, and `striptags`

Method calls are intentionally limited to the documented pure allowlist. `string.split(separator)` returns an array, `array.join(separator)` and `separator.join(array)` both return a string, `object.items()` returns key/value arrays for loop unpacking, and `object.get(key, default)` returns the default only when the key is absent. Mutating methods such as `append`, `extend`, `pop`, and `update` are not supported. `range()` is a built-in call rather than a method call; it produces an array of numbers and is capped at 10000 items.

Unsupported concepts must fail parsing or validation rather than no-op: import/from-import, raw blocks, dynamic include/extends paths, top-level child nodes outside blocks in extending templates, mutating or unsupported method calls, undefined macro calls, and custom extensions beyond the documented tests, methods, filters, range helper, and loader-backed include/inheritance subset.
